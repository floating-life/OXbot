# 花色与出牌后结构：feature version 2

旧80维只含点数和动作类型。同样点数的不同花色出法被当作同一输入，C++还会合并
这些候选。新224维同时升级了候选集合、编码、迁移、训练、NumPy/C++推理与权重格式。

## 输入合同

token历史保持48词表、最多512 token。前80维完全保留，新增维度只读取自己的手牌
及当前合法动作。先按真实card ID扣除动作，剩余库存才用于所有出后特征。

| 0-based位置 | 含义 | 归一化 |
|---|---|---|
| 0–79 | 旧特征，逐项保持 | 原合同 |
| 80–133 | 原手牌54面库存，含花色和大小王 | /2 |
| 134–187 | 出完候选后的54面库存 | /2 |
| 188–202 | 余牌15点数的天然牌计数，排除配子 | /4 |
| 203–204 | 余配子数、余牌张数 | /2、/27 |
| 205–212 | 天然牌计数至少1…8张的点数种数 | /15 |
| 213–214 | 五张顺子天然/允许配子窗口数 | /10 |
| 215–216 | 五张同花顺天然/允许配子窗口数 | /40 |
| 217–218 | 三连对天然/允许配子窗口数 | /12 |
| 219–220 | 两组三张钢板天然/允许配子窗口数 | /13 |
| 221 | 可行三带二点数组合数 | /182 |
| 222 | 可形成的最大同点数炸弹张数 | /10 |
| 223 | 是否持有四王炸 | 0/1 |

顺子覆盖A2345至10JQKA，连对覆盖A23至QKA，钢板覆盖A2至KA。
每个组合独立核算配子预算；三带二的三张与两张共用同一预算，joker附对须有两张
天然王。窗口潜力可重叠，不能把统计值解释成同时拥有多个互不重叠组合。

具体反例：级9，手牌 `[0,4,8,12,16,1,5,9,13,17,20,24]`。
红桃A2345与方块A2345原来产生完全相同的80维输入，打完后却分别保留1与3个天然
同花顺窗口。v2的剩余面库存和同花顺潜力会区分它们。

## 候选与算力预算

四种循环花色优先顺序各生成一组“天然牌优先、配子补缺”的合法代表，取并集。
同花顺仍覆盖各可行花色，普通顺子保留避免误判同花顺的修正。相同54面而不同副本
只留一个代表，按 `(type,key,size,claim ranks,action faces)` 固定排序。

通常最多256个候选：每种点数/牌型语义先保留一个，再轮询补充其他花色代表。
若语义本身超过256则全部保留，不丢弃整类合法出法。这是有界代表集合，不是所有
物理出牌子集的穷举；候选预算也不等同于整局时限保证。C++前置合法牌枚举与模型
推理的实际耗时仍须用目标平台测试。

## 权重和兼容性

| 路线 | 特征维度 | feature_version | 二进制magic/version |
|---|---:|---:|---|
| 旧模型 | 80 | 1（旧配置缺省） | FBDN001 / 1 |
| 组牌v2 | 224 | 2（必须明确） | FBDN002 / 2 |

旧NPZ/PT缺feature_version仍按v1解释；声明224却没有version2会被拒绝。
二进制header结构相同，但magic、version和维数必须匹配，首层权重形状必须一致。
不支持通过改文件名或伪造配置把80维权重变成224维。

`--warm-start ... --feature-dim 224` 会给 `hand_mlp.0.weight` 新增144个零列，
其余权重原样复制。初始化时新增信息不改变旧动作的分数，随后梯度可更新新列；
BC→DMC的正比例Q缩放仍单独记录。`--resume` 不隐式迁移，必须匹配原维度与版本。
Replay、actor、评测及Python参考Bot均按各自模型维度工作；与旧BC对战时，旧BC座位
继续用旧候选集合，避免改变基线来制造提升。

## 运行与验收

默认后训练入口已选择224维。在项目根目录：

```powershell
.\competition\scripts\posttrain_5080.ps1 -Out ckpts/posttrain-structure-v2
```

短验证使用 `-Smoke`，或在 `competition/` 中直接执行：

```bash
python posttrain.py --feature-dim 224 --smoke --out ckpts/structure-smoke-new
```

新的训练产物按模型配置自动导出FBDN002；C++源码必须用新构建，旧单文件源码不能
加载新格式。按 [C++部署说明](../../docs/fabledan_cpp.md)重新导出、amalgamate和验收。

已经验证：

- 全13等级、领出/跟牌及边界反例共186案例，17,871候选；两端顺序与224维float32值完全一致。
- 80→224初始化保持同输入分数/排序，新列能反向传播并更新；80维旧路径仍通过对齐。
- 真实RTX5080短流程完成迁移、DMC、复盘、纠错训练及评测；不是填零后直接交付为强模型。
- 真实224维产物导出FBDN002，与C++网络最大误差约6.29e-7，5种输入规模argmax全部一致。
- 本地官方裁判双贡完整1局，124次出牌均由新版模型选择，零错误，长时运行保活协议通过。

源码范围、兼容性、短训练及实际进程验收汇总见
[2026-10-03升级记录](../../reports/structure_v2_implementation_20261003.md)。

这些结果证明表示、训练与部署链路一致，不证明实战胜率提升。短流程产物仍没有
通过足量强度验收，不应替换线上权重。
